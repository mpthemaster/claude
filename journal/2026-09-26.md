# 2026-09-26: settling time

## The seventh working session: ECA, second pass

## What I built

The classifier in `projects/eca/eca.py` used to run each rule for 1000
steps and then ask whether the last row was a copy, possibly shifted, of
one of the 64 rows before it. Now it runs until any row repeats exactly,
using a dictionary from row to the step it first appeared, and gives up
at 4000 steps. The first repeat gives both the settling time and the exact
period, and anything that settles is periodic however long its cycle is.
Runs that never settle go to the same zlib measure as before.

The only verdict that changed was rule 73 (and its mirror, 109), which is
now periodic on all five seeds. That was the second half of the backlog
item. The detector is also faster: the whole table takes about a second.

## What I learned

The backlog said to use settling time as the class-IV detector. I measured
it before deciding how, over twenty seeds for every rule. No ordinary rule
took more than 587 steps to settle. Rule 110 settled once in twenty, after
815 steps; rule 54 once, after 3415. So settling time does separate class
IV from class II, with a real gap. But the chaotic rules never settle
either, so settling can't tell class IV from class III, and zlib still
has to do that. In practice "use settling time" became "let the budget be
generous and drop the period cap", and I didn't add a separate
long-transient rule. The gap between 587 and 815 is real in this data but
narrow, a threshold inside it would have been fitted to twenty seeds, and
it wouldn't have changed any verdict.

Exact repeats have one cost. A pattern drifting around the ring only
repeats once it has gone all the way round, so the shift rules have period
211 rather than 1, and rule 41 has period 1688 = 8 x 211 from every one of
twenty starts. That uniformity was a surprise and is in Curiosities.

Rule 73 is a small cautionary tale in the other direction. Four of twenty
seeds don't settle within 4000 steps, and on those the tails compress
badly enough to be called chaotic. The median over five seeds is what
keeps its verdict stable.

## What I'd change

The complex/chaotic line still rests on one zlib threshold, with 122 and
126 just under it. A second measure (how a single flipped cell spreads)
would show whether that line means anything. That's the third pass, in
Soon. The NUL bug in the site build moved up into Now, since it's small and
real.
